## Activation Contract
Load when editing `frontend/src` (React/TS), the `wails-service.ts` facade, event
subscriptions, or adding/refactoring UI panels.

## Hard Rules
- **Never edit `frontend/bindings/**`** — it is generated by Wails. After a
  backend change, run `npm run build` (or `wails generate`) to refresh it. Type
  mismatches mean the backend DTO changed; fix the backend/facade, not bindings.
- Consume the backend through a single typed facade `wails-service.ts` that maps
  generated `bindings.*` functions to a `DesktopService` interface
  (`frontend/src/wails-service.ts`). Components import the facade, never bindings.
- Subscribe to live updates via `@wailsio/runtime` `Events.On(...)` reading
  `event.data`. The event names are a stable contract: `mouse:status`,
  `mouse:configuration`, `mouse:polling-configuration`.
- Keep components **presentational**: they receive data and callbacks via props
  from `App.tsx` and hold no backend/business logic. Panels: `DpiPanel`,
  `PollingPanel`, `LightingPanel`, `MouseFeatures`, `Sidebar`, `TopBar`.
- Model types in `App.tsx` mirror the Go DTOs (camelCase). When the backend DTO
  changes, update the TypeScript type in `App.tsx`, not the generated bindings.
- Unsubscribe on unmount: `Events.On` returns an unsubscribe fn; call it in the
  `useEffect` cleanup (`frontend/src/App.tsx:53`).

## Frontier bar
- A frontier model never writes business logic inside a component; it lifts state
  and effects into `App.tsx` and passes pure props down.
- It treats `wails-service.ts` as the only place that knows about the generated
  binding names, so a backend rename touches exactly one file.
- It always pairs a live subscription with its cleanup to avoid leaked listeners.
- It regenerates bindings after backend changes and reconciles types in one pass.

## Decision Gates
| You need to… | Pattern |
| Call a backend method | use `desktopService.<Method>` from the facade |
| React to a push | `Events.On("mouse:...", e => cb(e.data))` + cleanup |
| Add UI surface | new presentational panel fed by `App.tsx` props |
| Backend DTO changed | update `App.tsx` types, regenerate bindings |

## Execution Steps
1. Add the backend method (see `wails-backend`); regenerate bindings.
2. Map the new binding in `wails-service.ts` and add it to `DesktopService`.
3. Mirror the DTO as a TypeScript type in `App.tsx`; pass it as props.
4. Add/extend a presentational panel; keep logic in `App.tsx`.
5. Subscribe to events with cleanup; run `(cd frontend && npm run build)`.

## Output Contract
Report the facade method added, the event subscribed, the panel changed, and
confirm `frontend/bindings` was not hand-edited and `npm run build` passed.
