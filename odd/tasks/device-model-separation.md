# Device model separation (X6 decoupling)

Objective: move every X6-specific piece behind a per-model driver under `internal/attackshark/x6` so generic code never imports a model. Branch: `refactor/device-model-separation` (from `feat/aur-packaging` @ 5511321). Delivery: `auto-chain`, `chain_strategy=feature-branch-chain`; push/PR are the user's decision. Runner: `go test ./...` (needs `cmd/x6configurator/frontend/dist`) and `cd frontend && npm test`.

## Specs

- S1 Decouple everything X6: "hay que desacoplar todo el x6" / "bueno demomento desacoplamos todo". Check: an import-boundary test fails when any package outside `internal/attackshark/...` and `cmd/...` imports `internal/attackshark/...`; at the end its allowlist of known violations is empty.
- S2 Per-model layout: "lo que va a ver que hacer es migrar lo de el x6 a attack-shark/x6 attack-shark/x11 o asi". Assumption: Go path `internal/attackshark/x6` (driver), `internal/attackshark/x6/protocol` (report codecs), `internal/attackshark/x6/macrocodec` (X6 macro codec and key table). `x11` is NOT created now.
- S3 Protocol lives in the model: "poqeu no tienen protocolos iguales". Check: no report encoding, ACK matching, VID/PID, HID usage, or X6 key table remains in generic packages (`transport`, `hidlinux`, `mouse`, `macros`, `desktop`, `configstore`).
- S4 Shared VID/PID is unresolved: "lo malo que el vid pid es lo mismo en los dos a si que no se como lo haremos". Not solved in this feature. Constraint (assumption): generic code obtains device identity from the registered model profiles, never from hard-coded IDs, so a later model resolver can be added in one place. Recorded as an open question.
- S5 Behavior unchanged (assumption from the proposal, not objected): identical HID bytes, identical persisted JSON (profile ID `attack-shark-x6`, model `Attack Shark X6`, configstore keys), udev rules, install paths, binary `cmd/x6configurator`, log names `x6_inventory`/`x6_desktop`, localStorage `x6.language`. Check: all pre-existing Go and frontend tests pass at every commit, moved with their code.
