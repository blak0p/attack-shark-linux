# Per-game profiles: launch wrapper and tray watcher
Objective: switch the mouse profile per game without a system service. Two independent deliverables: A) launch wrapper CLI, B) tray app with /proc watcher. Branch: not created yet; delivery strategy `ask-on-risk`; test runner: Go `go test ./...`, frontend Vitest, `make check`. Never write to real hardware in automated checks.

## Specs
S1. Wrapper command (A): `attack-shark-linux --profile <name> -- <command>`. Used as a Steam launch option (`... -- %command%`) and in other launchers. It applies the named profile, runs the command, waits for it, restores the previous profile, and returns the command's exit code. If the profile cannot be resolved or switched, it prints a warning and launches the game anyway; it must never block the game.
S2. Name resolution (A): the profile is selected by name (exact match, case-sensitive). Not found or ambiguous is a warning, not a failure of the game. A raw 32-hex profile ID is accepted as an escape hatch.
S3. Unique profile names (A prerequisite): Create, Rename and Duplicate must reject a name already in use. Existing duplicate names on disk must not break loading.
S4. App-running lock (A and B): the app takes an flock on a lock file at startup and releases it on exit (kernel releases it if the app crashes). The wrapper checks it. App open: the wrapper does not touch the mouse, it only launches the game, because the app owns the mouse. App closed: the wrapper applies the profile itself. Rule from the user: “depende si esta desde la app le hace caso a la app si no nada”.
S5. Switching to the already-active profile rewrites it anyway (accepted by the user: “lo mas facil lo rescribe”).
S6. Tray app with watcher (B, second phase): opt-in setting, off by default. When on, closing the window keeps the app in the system tray (Wails `Linux.DisableQuitOnLastWindowClosed` plus `SystemTray`). A selector in the app maps an executable (or launcher entry) to a profile. The app scans /proc every few seconds, applies the mapped profile when the executable appears and restores the previous one when it exits. Autostart is an opt-in toggle that writes/removes `~/.config/autostart/*.desktop`; nothing is installed system-wide and no systemd unit is used. If no tray exists (Hyprland without Waybar tray module), the window minimizes and the app stays alive.
S7. Memory footprint (decision): accept ~300 MB for the full app, no WebKit purge patch, no separate watcher binary. Trim frontend size before the release.
S8. Existing `reset` stays as is; connecting `reset` to profiles is a later task before the release (see T9).
S9. Duplicate name feedback in the UI (A prerequisite): creating, duplicating or renaming a profile with an already-used name must show an error and must not create or rename it. Name matching is case-sensitive. User: “te añado la tarea de ponerlo como error porfa que no deje crearlo que sea CareSensitive obvio”. Backend already rejects with code `duplicate_profile_name` (T1); the frontend has no message for that code yet (assumption: it currently shows the generic error).

S10. Launch command in the Games panel (user comment on the design): “por aqui añádiria el comando de como usarlo sin tener la app abierta para steam y eso”. The panel shows the wrapper command for a chosen profile with a Copy button and the Steam steps; it must shell-quote the profile name.
S11. Games panel (artboard design/game-profile-rules/02-games-panel.html, system design/system.md): a new `games` section in the workspace navigation with a master switch, an ordered rules table (executable, profile, move up/down, remove) where the first rule wins, an add-rule form, and the launch-command card. Rules store profile IDs; names are shown. Persistence goes through the existing backend `GetWatcherSettings` / `SetWatcherSettings`.

S12. Launch command uses the real executable path (decision proposed by the assistant, user did not object): the Games panel and README must not assume `attack-shark-linux` is on PATH. The backend exposes the running executable path (env `APPIMAGE` when set, else os.Executable()); the panel builds `"<path>" --profile "<name>" -- %command%` with both parts shell-quoted. No symlink or install step is created by the app. README documents the full-path form and the PATH form.
S13. Rules stay editable while the master switch is off (the rules are saved, only the watcher is inactive); a short helper line explains that the watcher is off. The artboard disabled the form, which made first use confusing (user screenshot).
S14. App picker (user, 2026-10-28): “para agregar una app es solo escribirla tio eso no funciona asi no la va a encontrar hay que hacer un esto que vea desktop y demas cosas que puedes acceder mediante lanzador de apps o como fallback al gestor de archivos”. Adding a rule picks from installed apps (.desktop entries from XDG data dirs, ~/.local/share/applications and Flatpak, with search) and falls back to a native file dialog (“Browse…”, Wails OpenFileDialog, GTK file chooser) whose result is stored as the executable base name; typing by hand stays as an advanced option. Store libraries (Steam appmanifest, Heroic, Lutris) come after, as their own task.
S16. Game rules by folder (user, 2026-10-28): “2 me gusta mucho es lo mejor si hace mach con algo de dentro va dentro porque se esta usando y el nombre es lo que ves tu lo bonito por ejemplo que sale en mis juegos de steam y de heoric que tengo instalados”. A rule can be a game: it has a display name (the Steam or Heroic title) and an install folder; it is active when any running process has a path inside that folder (exe link, cwd or a command-line argument, Wine/Proton paths included). Executable-name rules stay for apps. The picker lists installed games (Steam libraries from libraryfolders.vdf and appmanifest, Heroic, .desktop apps) by display name, plus Browse… for any file or folder. Existing watcher-v1.json rules keep working as executable rules.
S15. Autostart (user, 2026-10-28): “y para t8 seria en modo bandeja no la app completa”. The autostart entry starts the app in tray mode with no window created; depends on T6. Opt-in switch that writes/removes ~/.config/autostart/*.desktop.
